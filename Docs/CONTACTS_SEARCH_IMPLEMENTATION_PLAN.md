## 2. Модель и способ хранения

`Models/ProjectContact.swift`:

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | идентификатор. При старой миграции `StorageService.migrateContacts` мог выдать новый UUID |

Запись: `AppStore.addContact` / `updateContact` / `deleteContact` → `persistProjects()`, кроме DEMO. Поиск этот путь не вызывает.

## 5. Правила нормализации

Сравнение только в памяти. `phone` на диске не менять. Звонок не переписывать.

Текст (`name`, `role`, `note`):

1. Обрезать пробелы по краям запроса.
2. Схлопнуть повторяющиеся пробелы в один.
3. Пустой запрос → весь список.
4. Совпадение, если нормализованный запрос входит в поле как подстрока.
5. Регистр не учитывать: `localizedStandardContains` (кириллица, латиница, диакритика средствами системы).
6. Отдельную таблицу `ё`/`е` и транслит не делать. Если локаль системы считает их равными, это допустимо; отдельной гарантии нет.
7. Несколько слов ищутся как одна подстрока: «иван пет» находит «Иван Петров». «пет иван» не обязан найтись.
8. Fuzzy search нет.

Телефон, дополнительно:

1. Из запроса и из сохранённого номера оставить только десятичные цифры.
2. Канал телефона включать, если в запросе есть хотя бы 3 цифры. Одна цифра `7` или `8` не должна показывать всю книжку.
3. Ключ номера: если цифр 11 и первая `8`, для сравнения заменить её на `7`. `+7` и `8` у полного номера сходятся. Сохранённая строка не меняется.
4. Если цифр 11 и первая `7`, дополнительный ключ — последние 10 цифр.
5. Совпадение, если ключ сохранённого номера содержит ключ запроса.
6. Пробелы, скобки и дефисы в цифровой канал не входят.
7. Телефонный канал включается только по числу цифр после нормализации. `+`, пробелы и прочие символы сами по себе его не включают. При меньше чем трёх цифрах исходная форматированная строка телефона отдельно не сравнивается: `7`, `8`, `+7`, `+7 ` и `+79` номер не находят. `+791` уже может. Имя, роль и заметка ищутся при любом непустом запросе, поэтому текст `Бригада +7` по запросу `+7` находится как текст, а не из-за номера.

Примеры только для сравнения:

| Сохранено | Запрос | Результат |
| --- | --- | --- |
| `+7 (900) 123-45-67` | `900123` | найден |
| `+7 900 123-45-67` | `89001234567` | найден |
| `89001234567` | `+7 900` | найден |
| `+7 900 111-22-33` | `8` | не найден телефонным каналом (меньше 3 цифр) |

## 6. Предлагаемый UX

На `ProjectContactsListView`:

```swift
.searchable(text: $query, prompt: "Поиск контактов")
```

- системная очистка и скрытие клавиатуры;
- фильтр на каждый ввод;
- сортировка та же: избранные, затем имя;
- данные не пишутся;
- звонок, карандаш, `+` и свайп удаления остаются на видимых строках.

Дашборд и избранные не фильтровать.

Пустое состояние проекта заменить на запрошенный текст, кнопку `+` оставить:

```text
Контакты не добавлены
```

Это сознательная замена текущей фразы «Контактов пока нет…».

## 7. Состояния интерфейса

| Состояние | Условие | Экран |
| --- | --- | --- |
| Нет контактов | массив проекта пуст, запрос любой | «Контакты не добавлены» и `+`. Поле поиска можно не акцентировать |
| Пустой запрос | контакты есть | полный отсортированный список |
| Есть совпадения | запрос не пуст | тот же вид строк, меньше элементов |
| Нет совпадений | контакты есть, фильтр пуст | «Ничего не найдено» и «Попробуйте изменить запрос.» `+` остаётся |

«Ничего не найдено» не показывать, когда в проекте нет контактов.

## 8. Поток данных

```text
Project.contacts
  → сортировка в памяти
  → если запрос пуст, весь список
  → иначе фильтр по name / role / phone / note
  → List
```

`@State query` живёт на экране списка. Закрытие sheet его сбрасывает. Это не настройка проекта.

Редактирование и удаление идут в `AppStore` как сейчас. Список пересчитывается из `store.projects`. Если после правки контакт больше не совпадает, он исчезает из результатов, запрос остаётся. Удаление берёт контакт из **показанного** массива по id. Нельзя удалять по индексу исходного JSON.

## 12. Проверки

- проект без контактов: «Контакты не добавлены», `+` работает;
- один контакт и несколько;
- имя, часть фамилии внутри `name`, роль, компания если она записана в `name` или `role`;
- телефон: `+7`, `8`, пробелы, скобки, дефисы, часть номера от 3 цифр;
- email не ищется, поля нет;
- заметка находит контакт, строка остаётся прежней;
- кириллица, латиница, разный регистр;
- пробелы по краям и повторные пробелы;
- часть слова;
- «Ничего не найдено» не путается с пустым проектом;
- очистка возвращает полный список;
- правка при активном поиске не пишет лишнего и обновляет список;
- удаление из результатов удаляет один контакт и не сдвигает чужие;
- после закрытия редактора поиск на месте;
- избранные остаются сверху;
- звонок с той же строки;
- iPhone и iPad: sheet и поле поиска;
- Dynamic Type не обрезает имя и пустые тексты;
- VoiceOver читает поле поиска, строку и оба пустых состояния;
- обычный проект 1.0.3 открывается без пересохранения;
- подписки и DEMO не изменены.
