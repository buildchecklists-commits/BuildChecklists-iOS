# BuildChecklists — обзор проекта

**Платформа:** iOS (SwiftUI)  
**Текущий релиз:** App Store **1.0.3**, Build **9**  
**Bundle ID:** `com.mikhail.buildchecklists.arm`  
**Эта папка — единственный источник истины для iOS.**  
Старые копии (BuildChecklists 2, BuildChecklists 3) для разработки не используются.

Код приложения в этом документе не описывается как «что менять». Документ фиксирует, как система устроена сейчас.

---

## Назначение приложения

BuildChecklists — локальное приложение для контроля частного строительства.

Пользователь ведёт объект по этапам: геология, фундамент, стены, перекрытия, крыша, покрытие крыши, инженерия, окна, двери, отделка, благоустройство. На каждом этапе есть чек-листы типичных работ и ошибок, фотофиксация, сроки, расходы и план/факт бюджета.

Приложение работает **без сервера**. Все пользовательские данные живут на устройстве. Доступ к редактированию определяется подпиской App Store (StoreKit 2). Есть сессионный DEMO-режим с готовым учебным проектом.

---

## Основные возможности

- Онбординг из 6 экранов и экран «Что нового» после обновления версии.
- Локальный профиль (имя, email, пароль хранится локально; бэкенда нет).
- DEMO-режим: один учебный объект с прогрессом, фото, расходами, бюджетом и подсказками.
- Проекты: создание, карточка, обложка, цвет, типы конструкций, контакты, файлы.
- Чек-листы по типу конструкции (например, ленточный фундамент ≠ сваи).
- Тексты «Инфо» по пунктам (markdown в бандле, ~674 файла).
- Сроки этапов: план, факт, причины просрочки, вкладка «Сроки».
- Расходы: материалы / работа / аренда, привязка к этапу, графики, экспорт CSV/PDF.
- Бюджет: общий бюджет объекта + плановый бюджет по стадиям + план/факт.
- Глобальная лента фото по всем проектам и этапам.
- Задачи с локальными уведомлениями.
- Калькуляторы материалов (бетон, арматура, блоки, штукатурка и т.д.).
- Подписки USER (до 2 проектов) и PRO (без лимита). Истёкшая подписка — только просмотр.
- Удаление аккаунта с полной очисткой локальных данных (требование App Review 5.1.1(v)).

## Жизненный цикл приложения

1. Запуск `BuildChecklistsApp`: создаётся `AppStore`, применяется тема и акцентный цвет.
2. `RootView`:
   - если онбординг не пройден (`bc_has_seen_onboarding`) → `OnboardingView`;
   - если пользователь зарегистрирован **или** включён DEMO → `MainTabView`;
   - иначе → `WelcomeView`.
3. После появления Welcome/Main вызывается `store.bootstrap()`:
   - флаг регистрации;
   - локальная роль;
   - DEMO на холодном старте **не** включается;
   - проверка StoreKit entitlements;
   - загрузка seed-этапов;
   - загрузка проектов / расходов / задач с диска (если не DEMO).
4. Пользователь работает во вкладках: Проекты, Сроки, Бюджет, Фото, Профиль.
5. При обновлении версии, если `CFBundleShortVersionString` не совпадает с сохранённым значением, показывается `WhatsNewView`.

DEMO включается только кнопкой «Попробовать демо» и живёт до закрытия приложения / выхода в регистрацию. Подробности — `DEMO_MODE.md`.

## Основные сущности

| Сущность | Смысл |
|---|---|
| `Project` | Объект строительства. Содержит метаданные, контакты, файлы, общий бюджет, план по стадиям и `stages` для **таймлайна**. |
| `Stage` | Этап. В таймлайне — даты и просрочки. В ProgressStore — рабочий чек-лист выбранного типа конструкции. |
| `StageItem` | Пункт чек-листа: статус `ok / issue / na`, фото, PDF, `infoSlug`. |
| `ExpenseItem` | Расход (факт). |
| `TaskItem` | Задача, опционально привязанная к проекту. |
| `ProjectContact` | Контакт по объекту. |
| `UserRole` | `demo` / `user` / `pro`. Не путать с флагом `isDemoMode`. |
| JSON-паки | Шаблоны рабочих чек-листов в `Resources/Seeds/*Packs`. |
| `stages.json` | Шаблоны **глобальных** этапов таймлайна, не рабочие чек-листы объекта. |

Два контура чек-листов — ключевая особенность продукта. Их нельзя смешивать без отдельного решения. См. `ARCHITECTURE.md`.

## Что является источником истины

| Вопрос | Источник истины |
|---|---|
| Код и поведение iOS | Эта папка проекта, релиз 1.0.3 / Build 9 |
| Перенос на Android | Поведение этого iOS-приложения (`ANDROID_SYNC.md`) |
| Метаданные проекта, сроки, контакты, общий/плановый бюджет | `AppStore.projects` ↔ `build_checklists_projects.json` |
| Расходы (факт) | `AppStore.expenses` ↔ `build_checklists_expenses.json` |
| Задачи | `AppStore.tasks` ↔ `build_checklists_tasks.json` |
| Прогресс рабочих чек-листов, статусы пунктов, фото пунктов | соответствующий `*ProgressStore` |
| Право редактировать и лимит проектов | StoreKit entitlements через `SubscriptionService` |
| Сессионный DEMO | флаг `AppStore.isDemoMode` (не сохраняется как роль) |
| Тексты «Инфо» и состав шаблонных чек-листов | бандл: `Resources/InfoTexts`, `Resources/Seeds` |
| Тема, онбординг, «Что нового», имя/аватар профиля | UserDefaults / AppStorage |

**Для UI прогресса объекта источником истины являются ProgressStore**, а не `Project.stages`.  
`Project.stages` — источник истины для вкладки «Сроки» и причин просрочки.

Несогласованность этих двух контуров — известный архитектурный факт, а не баг «на потом забыть». Менять один без другого нельзя.
